THE FIRST START TAKES A WHILE
  SteamCMD installs the game -- about 3GB on disk -- before the server can
  answer anything, and the pod stays un-Ready throughout. How long that takes
  depends on your connection. The startup probe allows {{ mul .Values.probes.startup.failureThreshold .Values.probes.startup.periodSeconds | div 60 }} minutes for it.

  Some restarts during the first install are expected: SteamCMD intermittently
  fails with "Missing configuration" and exits 8. Each restart resumes the
  download. Only worry if it is still looping after several attempts.

  Watch progress with:
    kubectl --namespace {{ .Release.Namespace }} logs -f \
      deployment/{{ include "satisfactory-server.fullname" . }}

{{- if .Values.persistence.gamefiles.enabled }}

  You can ignore the "Checking available storage" warning during this. It
  measures /config, but the game installs into the separate gamefiles volume.
{{- end }}

  If the startup probe gives up before the install finishes, the pod restarts
  and loses nothing, but you should raise probes.startup.failureThreshold
  (currently {{ .Values.probes.startup.failureThreshold }} attempts, every {{ .Values.probes.startup.periodSeconds }}s).

HOW TO CONNECT
{{- if eq .Values.service.type "LoadBalancer" }}
  Get the external address once it is assigned:

    kubectl --namespace {{ .Release.Namespace }} get svc -w \
      {{ include "satisfactory-server.fullname" . }}

  Then in Satisfactory: Server Manager -> Add Server, using
  <EXTERNAL-IP>:{{ .Values.server.gamePort }}
{{- else if eq .Values.service.type "NodePort" }}
  Find the assigned node port:

    kubectl --namespace {{ .Release.Namespace }} get svc \
      {{ include "satisfactory-server.fullname" . }} \
      -o jsonpath='{.spec.ports[?(@.name=="game-tcp")].nodePort}'

  Connect to <ANY-NODE-IP> on that port. The UDP port must be forwarded too, or
  the client will find the server but never finish joining.

  IMPORTANT: the game does not support port redirection on {{ .Values.server.gamePort }}. If the
  node port above is not {{ .Values.server.gamePort }}, players cannot join, however the firewall
  is configured. Node ports come from 30000-32767 unless the API server is
  started with a wider --service-node-port-range. See docs/networking.md.
{{- else }}
  The Service is ClusterIP, so it is not reachable from outside the cluster.
  For a quick test:

    kubectl --namespace {{ .Release.Namespace }} port-forward \
      svc/{{ include "satisfactory-server.fullname" . }} {{ .Values.server.gamePort }}:{{ .Values.server.gamePort }}

  Note that port-forward only carries TCP. Joining a game needs UDP as well, so
  use a LoadBalancer or NodePort for anything beyond checking the API responds.
{{- end }}

CLAIM THE SERVER
  A fresh server is unclaimed and will not accept a game until someone does so.
  This cannot be automated from the chart. In the game client, add the server,
  set an administrator password when prompted, name the server, then create or
  upload a save.

NOTE: a NetworkPolicy restricts egress. The server contacts Steam on every start
